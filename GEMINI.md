# Me and my Blade — Проектные правила и контекст

## 1. Общие сведения о проекте
- **Название:** Me and my Blade
- **Жанр:** Динамичный FPS Melee Action / Slasher в стиле **ULTRAKILL** и **Mordhau** (высокий темп, размашистые атаки, честные физические хитбоксы, парирование, арены).
- **Стек:** Unity 6000.6.2f1, Universal Render Pipeline (URP), New Input System (`UnityEngine.InputSystem`).
- **Контроль версий:** Git + GitHub Desktop (`master` ветка). Все изменения отслеживаются через Git. Коммиты в основном фиксирует разработчик.

---

## 2. Архитектура и критические правила кода

### Ядро боевой системы: `MeleeWeapon` и `Health`
- Скрипты `MeleeWeapon` и `Health` универсальны. Они не привязаны к конкретным сущностям (игрок или враг) и масштабируются без изменения базового кода:
  ```
  MeleeWeapon.OnTriggerEnter(Collider other)
      → Health target = other.GetComponentInParent<Health>();
      → Parry parry = other.GetComponentInParent<Parry>();
      → Если parry != null && parry.IsParrying && parry.CanParryFacing(attackerPos): parry.OnSuccessfulParry()
      → Иначе: target.TakeDamage(damage)
  ```
- **Именование колбэка:** Метод в `MeleeWeapon` называется строго `OnTriggerEnter`.
- **Физика триггеров (PhysX):** Для гарантированной регистрации триггеров движущийся хитбокс обязан иметь `Rigidbody` с `isKinematic = true`.
- **Слои (LayerMask):** `Player` (слой 6, маска 64) и `Enemy` (слой 7, маска 128). Поле `targetLayers` у каждого оружия настраивается на противоположный слой.

### Архитектура оружия: Socket / Weapon
- Контейнеры оружия (`PlayerWeapon`, `EnemyWeapon`) выступают в роли точки крепления (слота/руки).
- Скрипты `PlayerCombat` и `Enemy` принимают ссылку на контейнер `GameObject weapon` и автоматически находят активный компонент `MeleeWeapon` на нём или в дочерних объектах (`GetComponentInChildren<MeleeWeapon>()`).
- Конкретное оружие (`Sword` и будущие виды оружия) содержит собственный `Collider` (хитбокс `isTrigger`), визуал, `Animator`, кинематический `Rigidbody` и скрипт `MeleeWeapon`.
- **Устаревшие костыли упразднены:** `ColliderProxy.cs` и `HitboxForwarder` удалены — триггер меча обрабатывается напрямую тем же объектом, на котором размещён `MeleeWeapon`.

### Анимации и события аниматора
- Контроллеры анимаций разделены:
  - `PlayerWeapon.controller` — оружие игрока (поддержка состояний `Swing1`, `Swing2`, `Swing3`, `Parry`, `Idle`);
  - `EnemyWeapon.controller` — оружие врага (состояния `Swing`, `Parry`, `Idle`).
- Переходы в состояние `Parry` настроены без задержек (`Has Exit Time = false`, `Transition Duration = 0`).
- Во всех боевых клипах (`Swing.anim`, `Swing2.anim`, `Swing3.anim`) настроены Animation Events:
  - `HitboxOn` (включение коллайдера);
  - `HitboxOff` (выключение коллайдера и открытие окна комбо);
  - `SwingEnd` (сброс флага замаха, шага комбо и триггера).
- Комбо-система: 3-ударная цепочка (`Swing1` -> `Swing2` -> `Swing3`), управляемая через `MeleeWeapon.cs` (`CrossFadeInFixedTime` по состояниям `Swing1`/`Swing2`/`Swing3` с буферизацией `comboQueued` и обратной совместимостью через `SwingTrigger` для врагов).

### Парирование (`Parry.cs`)
- Универсальный компонент для игрока и будущих элитных врагов.
- Поддерживает проверку угла обзора `CanParryFacing` (защита от ударов со спины).
- В `MeleeWeapon` предусмотрен буфер снисходительности `parryGraceWindow` для парирования на стыке контакта.

### Перемещение игрока (`FirstPersonPlayerController`)
- Кастомный контроллер от первого лица на `CharacterController`.
- Импульсы, рывки и отдача реализуются через `AddImpulse(Vector3 impulse)` с затуханием `impulseDecay`.

### ИИ врагов (`Enemy.cs`)
- Базируется на `NavMeshAgent` (FSM: `Chase`, `Attack`, `Dead`).
- Таран игрока исключён: дистанция атаки `attackRange = 2.2`, порог сближения `1.8м`, принудительный сброс скорости `agent.velocity = Vector3.zero`.

## 3. Правила написания кода и взаимодействия для ИИ-ассистента
- **Чистота и лаконичность:** Запрещены избыточные комментарии, очевидные XML-документации и атрибуты `[Tooltip]` в C# коде. Код должен быть чистым и самодокументируемым.
- **Запрет несогласованных Tool/Editor скриптов:** Не создавать вспомогательные скрипты редактора. Все действия по настройке объектов давать пошагово для интерфейса Unity (Inspector/Hierarchy). При крайней необходимости тулзов — строго сначала запрашивать согласие разработчика.
- **Экономия токенов:** Формулировать мысли компактно, избегать повторов и лишней генерации некритичного кода.
- Все подробные объяснения причин, логики и деталей реализации даются разработчику **в чате**, а не в комментариях к коду.
- Использовать исключительно **New Input System** (`UnityEngine.InputSystem`).
- Не создавать монолитные спагетти-скрипты, сохранять модульность и задел под масштабирование.

## 4. Текущее состояние систем (Status Quo)
1. **Перемещение:** Базовый контроллер готов. Дэш (Shift) ожидает реализации.
2. **Бой и урон:** Хитбоксы регистрируют урон напрямую через PhysX без костылей-форвардеров. Оружие подтягивается из слотов `PlayerWeapon`/`EnemyWeapon`.
3. **Парирование:** Окно парирования работает, кулдаун снижен до 0.2с со мгновенным сбросом при успешном дефлекте для отражения серий атак. Требует полировки импакта (стан, отдача, звук/партиклы).
4. **ИИ врагов:** Враг атакует на дистанции 2.2м, кулдаун атаки снижен до 1.0с для повышенной динамики боя.
5. **Комбо-система и анимации атак игрока:** Реализована и полностью отполирована 3-ударная цепочка (Swing1: верх-право -> низ-лево; Swing2: низ-лево -> верх-право; Swing3: вертикальный разруб по центру). Все три клипа стабилизированы (устранены рывки, паразитные перевороты по осям, зависания по Y и двойные проседания). Устранено дублирование кривых редактора, физические и редакторские кривые синхронизированы 1:1.

## 5. Ближайший план разработки (Roadmap)
1. **Сочность парирования и реакция врага:**
   - Состояние **Stun** при успешном парировании (оглушение врага на 1-2 сек с прерыванием атаки).
   - Нокбэк врага назад.
   - Визуальный/аудио импакт (Hit-Stop микропауза на ~0.05-0.08с, вспышка искр).
2. **Мобильность (Дэш на Shift):**

3. **Игровой цикл:**
   - Спавнер врагов волнами на арене.
   - Условия победы и поражения (HUD здоровья, счётчик волн).
4. **Расширение боевого арсенала:**
