# Me and my Blade — Проектные правила и контекст

## 1. Общие сведения о проекте
- **Название:** Me and my Blade
- **Жанр:** Динамичный FPS Melee Action / Slasher в стиле **ULTRAKILL** (высокий темп, отзывчивое управление, парирование, арены).
- **Стек:** Unity 6000.6.2f1, Universal Render Pipeline (URP), New Input System (`UnityEngine.InputSystem`).
- **Контроль версий:** Git + GitHub Desktop (`master` ветка). Все изменения отслеживаются через Git.

---

## 2. Архитектура и критические правила кода

### Ядро боевой системы: `MeleeWeapon` и `Health`
- Скрипты `MeleeWeapon` и `Health` являются универсальным ядром. Они **не знают**, кому принадлежат (игроку или врагу), и масштабируются без изменения своего базового кода:
  ```
  MeleeWeapon.OnTriggerEnter(Collider other)
      → Health target = other.GetComponentInParent<Health>();
      → Parry parry = other.GetComponentInParent<Parry>();
      → Если parry != null && parry.IsParrying: parry.OnSuccessfulParry() (урон поглощен)
      → Иначе: target.TakeDamage(damage)
  ```
- **Именование колбэка:** Метод в `MeleeWeapon` должен называться **строго `OnTriggerEnter`**! Попытки переименовать его (например, в `OnHit`) ломают пересылку событий триггеров из Unity.
- **Проксирование коллайдеров:** Физический триггер-коллайдер меча висит на дочернем объекте `Sword`. Для проброса событий на родительский объект с `MeleeWeapon` используется `ColliderProxy.cs`.
- **Слои (LayerMask):** `Player` и `Enemy`. Поле `targetLayers` у каждого оружия настраивается на противоположный слой.

### Анимации и события аниматора
- Контроллеры анимаций разделены:
  - `PlayerWeapon.controller` — оружие игрока;
  - `EnemyWeapon.controller` — оружие врага.
- В клипе `Swing.anim` настроены Animation Events:
  - `HitboxOn` (включение коллайдера);
  - `HitboxOff` (выключение коллайдера);
  - `SwingEnd` (сброс флага замаха и триггера).
- **Внимание:** Не добавлять вызовы методов в анимационные клипы, если эти методы не объявлены на том же объекте, где висит компонент `Animator`.

### Перемещение игрока (`FirstPersonPlayerController`)
- Кастомный контроллер от первого лица на `CharacterController`.
- Тонко настроенная физика: переменная высота прыжка с отсечкой (`jumpCutMultiplier`), раздельные ускорения/торможения на земле и в воздухе, скольжение по стенам.
- **Система импульсов:** Любые рывки, отдача и нокбэк реализуются через `AddImpulse(Vector3 impulse)` с затуханием `impulseDecay`.

### ИИ врагов (`Enemy.cs`)
- Базируется на `NavMeshAgent` (FSM: `Chase`, `Attack`, `Dead`).
- Навигация по сцене запекается через компонент `NavMeshSurface`.

## 3. Текущее состояние систем (Status Quo)
1. **Перемещение:** Отзывчивый контроллер готов. Дэш (Shift) пока **не реализован**.
2. **Бой:** Взмахи мечом с хитбоксами работают у игрока и врагов.
3. **Парирование (V1):** Работает на `Parry.cs` через таймер-окно игрока (0.3с по нажатию кнопки). Урон блокируется, но **враг пока никак не наказывается** (нет стана и отдачи).
4. **Сцена:** `TestChamber.unity` с запеченным NavMesh и тестовыми препятствиями.

## 4. Ближайший план разработки (Roadmap)
1. **Мобильность (Дэш на Shift):**
   - Добавить `dashAction`, `dashImpulse`, `dashCooldown` в `FirstPersonPlayerController.cs`.
   - Использовать существующий метод `AddImpulse()`.
2. **Сочность парирования и реакция врага:**
   - При успешном парировании переводить врага в состояние **Stun** (оглушение на 1-2 сек с прерыванием текущей атаки).
   - Добавить нокбэк врага назад.
   - Визуальный/аудио импакт (микропауза времени Hit-Stop на ~0.05-0.1с, вспышка партиклов).
3. **Вариации атак:**
   - Добавить вариативность взмахов оружия (разные анимации ударов).
4. **Игровой цикл:**
   - Спавнер врагов волнами на арене.
   - Обработка победы/поражения.

## 5. Инструкции для ИИ-ассистента
- Всегда следовать архитектурным принципам из раздела 2.
- Использовать исключительно **New Input System** (`UnityEngine.InputSystem`).
- Сохранять чистоту кода, избегать монолитных спагетти-скриптов.
- Код комментировать на русском языке при необходимости.
